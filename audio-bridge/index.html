AUDIO BRIDGE

Route an Audient iD4 input to a virtual microphone for BIGO Live, with headphone monitoring, 75% default software gain, mute and live input metering.

⬇ Download repository ZIPInstallation instructions

Download the repository ZIP and extract audio-bridge/app/. This is Python source with a Windows EXE build script, not a precompiled standalone EXE. The proposed neon GUI has not yet been implemented.

🎤 Audient iD4 → 🐾 Audio Bridge → 🔌 VB-CABLE → 📡 BIGO Live
Headphone monitor: Audient output · Default software gain: 75%

Setup in six steps

1. Drivers

Install Audient's Windows driver and VB-CABLE, then restart.

2. Extract

Download the repository ZIP and extract the audio-bridge/app folder.

3. Launch

Install Python 3 and run INSTALL_AND_RUN.bat. For a portable Windows EXE, run BUILD_EXE.bat on Windows.

4. Input

Select Audient iD4 recording input; start with 75% software gain.

5. Outputs

Select CABLE Input for broadcast and Audient headphones for monitoring.

6. BIGO

Start Bridge, then choose CABLE Output as BIGO's microphone. Test before going live.

⚠ Never connect an amplified speaker output directly to the iD4. Cubase ASIO playback needs a separate Windows-accessible loopback recording endpoint; it is not automatically captured.

FAQ & troubleshooting

Is this a standalone EXE?

Not yet. Build the Windows EXE from source using BUILD_EXE.bat. The generated EXE does not require Python on the destination machine, but system audio drivers are still needed.

Why does BIGO use CABLE Output?

The bridge plays audio into VB-CABLE's playback endpoint, CABLE Input. BIGO records it from CABLE Output.

Can I capture Cubase?

Only when Cubase playback is exposed through a Windows-accessible recording or loopback device. iD4 MKII loopback may help; ASIO audio is not captured automatically.

No sound?

Check the input meter, Windows microphone privacy settings, Audient drivers, VB-CABLE installation and BIGO's selected microphone. Cubase may hold the device exclusively.

Distortion or dropouts?

Lower analog gain and software gain, align devices to 48 kHz where supported, use headphones and close conflicting applications. Separate audio clocks can drift.

Feedback or echo?

Use headphones. Do not feed BIGO return audio back into the same virtual microphone.

Does it route to BIGO on my phone?

Not directly. This version targets BIGO on Windows; phone streaming requires additional compatible hardware/routing.

Pre-release bug report

Static source compilation was checked in the development environment. Windows hardware, BIGO reception and compiled EXE were not tested.

Known limitations

Simple Tkinter GUI; mono capture duplicated to stereo; fixed 48 kHz; possible clock drift; no automatic reconnect after device removal.

Manual QA checklist

Test Audient detection, live meter, monitoring, mute, BIGO reception, Cubase open/closed and a 30-minute continuous session.

Report a bug on GitHub. Include Windows version, iD4 model, device names and reproduction steps.
